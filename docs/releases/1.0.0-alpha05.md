把远端 DSH 连接失败从「崩溃宿主」改成「可读错误」。

### 修复
- ACP 连接建立期间，如果远端 `dsh` 不存在、ssh 进程提前退出，向已关闭的 stdin 写入会异步抛 `error`；此前没有监听器，Node 的未处理事件会让**整个 DSH Host 进程崩溃**。现在该错误被接住，连接以 `cannot open the ACP link to <instance>: …` 失败，界面/工具得到一句正常错误。
- 补了回归测试：模拟子进程在写入时退出，断言抛可读错误且进程不崩。

### 安装
```sh
dsh plugin --profile web add @kaus-io/dsh-remote-instance@1.0.0-alpha05
```

### 兼容性
`engines.dsh`: `>=0.2.1-rc.3 <0.3.0`

### 说明
上一版 `1.0.0-alpha04` 已发布，因此这次修复按版本号规则升到 `1.0.0-alpha05`。
